TEGOLA-SERVER · LOOKUP API 0.2.0
A hundred sources, one shape. Every call counted, every answer kept.
The Lookup API (barcode, identify, match, works) is what the app sees. Behind it sit 50 to 100 sources, each with its own client generated from its OpenAPI file. Between the two sits one layer: the DataProvider. It says what a source can do, for which types, how well, at what price, and how long its answers may be kept. Nothing above it knows a source's name.

01 · THE PROTOCOL
Providers return evidence, not answers.
An adapter wraps one generated client and translates its replies into ProviderRecords keyed by the type file's field keys. It never ranks, merges or decides. The router merges records from several providers into the API's Candidate, with reasons and sources filled from what each record says.

03 · METERING AND CACHE
One ledger row per outbound call. Cache hits are rows too.
Precision comes from metering at the transport, not in each adapter: a middleware on every generated client writes the row, so a new source can't forget. The provider's own invoice is reconciled against the ledger monthly.

TTL is the shorter of our default and the provider's licence (cachePolicy). A source that forbids storage is marked .passThrough and is never in the cache.
Tension with "no accounts" (ADR-0001)
Cost per user needs something to group by. The only id the server has is the App Attest key, which is per install. Proposal: store HMAC(keyID, monthly salt), so rows group within a month but can't be linked across months or to a person. Per-user figures are monthly aggregates by type; raw rows are deleted after 35 days. If the subscription later comes with a StoreKit transaction id, that id can be linked the same way, still with no name.
04 · PHOTO RECOGNITION
Recognition is a provider that returns hints, not records.
A recognizer turns a photo into the same IdentifyHints the app already sends (title, subtitle, catalogue number, OCR text). Those hints then go through normal routing. When the model moves to the phone, the server just stops receiving photos: the contract doesn't change.
