## What works

- **Keys and challenges in Postgres** (`PostgresStore`): registered App Attest keys survive restarts, and of
  concurrent replays exactly one passes, across any number of instances. The counter rule is one conditional `UPDATE`;
  re-registration keeps the stored counter and revocation.
- **Required in production.** A production server without `TEGOLA_DATABASE_URL` refuses to start. The URL defaults to
  `sslmode=verify-full`, and the password is never printed (not in `description`, `debugDescription` or a dump).
- **Migrations** are versioned, transactional, serialised by an advisory lock, and run before the port opens. A
  database that doesn't answer within 60 seconds stops the server.
- **Failures are honest.** A store that can't answer gives 503 with `Retry-After` for signed calls and registration,
  never a 401 that would make the app drop its key, never a pass. `/health` says `degraded`.
- **The Compose stack** runs Postgres 17:
  - on an internal-only network that only the server joins, with no published port;
  - read-only, with minimal capabilities and `scram-sha-256`;
  - with data in the `postgres_data` volume, backup in `docs/DEPLOY.md`.
- **CI** runs the store tests against a Postgres service on every push.

## Found on the way

- **The generated server drops an `undocumented` response's headers and body.** M1's "challenge store full" and
  `getWork`'s source outage went out as empty 503s without `Retry-After`. Handlers now throw `ServiceUnavailable`, and
  the edge middleware answers it (D-18).
- **`refusesToStart` cases now name their reason.** Once a database became required in production, every
  production case would have been refused for that reason alone. Each case now checks that the message names its own
  setting.
- A docs edit truncated `docs/DEPLOY.md` in the working tree. It was restored from git before the commit.
